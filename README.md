# MAX2TG-Bridge

> Двусторонний мост между мессенджером **MAX** (`web.max.ru` / `api.oneme.ru`) и **Telegram** через форум-топики в супергруппе.

Проект развивает [ircitdev/MAX2TG-Bridge](https://github.com/ircitdev/MAX2TG-Bridge) и сохраняет благодарность первоисточнику и его авторам.

## Чем этот форк отличается от оригинала и похожих проектов

Помимо форк-первоисточника [ircitdev/MAX2TG-Bridge](https://github.com/ircitdev/MAX2TG-Bridge), для контекста стоит знать про [Aist/max2tg](https://github.com/Aist/max2tg) 

Этот форк, начав с той же базы, что и ircitdev (форум-топики, один MAX-чат = один топик), добавил:

- **Маршрутизация в несколько Telegram-супергрупп** — не только разные топики одной группы, а разные MAX-чаты в разные Telegram-группы: вручную через `/bind`/`/add` в нужной группе или заранее через `MAX_CHAT_ROUTES`
- **Исправлен баг с именем топика** — раньше при добавлении бота в свежесозданную MAX-группу топик называли именем того, кто добавил, а не именем группы; теперь имя запрашивается у MAX напрямую, если его ещё нет в стартовом снепшоте
- **Полный переход на [PyMax](https://github.com/MaxApiTeam/PyMax)** вместо самодельного реверс-инженерного WebSocket-клиента — более стабильный протокольный слой
- **Persistent SQLite outbox с retry** в обе стороны — сообщения не теряются при временных сбоях сети или падении обработчика, а переживают рестарт процесса
- **Голосовые из Telegram реально доходят до MAX** — апстримный pymax отправляет их так, что MAX молча отвергает запись (`BAD_REQUEST`/`AUDIO_VALIDATION_FAILED`, см. [PyMax#103](https://github.com/MaxApiTeam/PyMax/issues/103)); здесь загрузка приведена к тому, что MAX действительно принимает: multipart-форма вместо сырого тела, ссылка на вложение по `audioId` вместо токена video-пайплайна и перекодирование записи в Opus 48 кГц моно через ffmpeg
- **Read-receipts и реакции пробрасываются между MAX и Telegram** — когда собеседник читает сообщение в MAX, на последнее переданное в Telegram сообщение ставится реакция ✅; реакции на сообщения в MAX отражаются строкой в топике
- **Полная загрузка видео** (опкод `VIDEO_DOWNLOAD_URL`) вместо одного превью-кадра; скачивание файлов по `fileId`, если нет прямого URL
- **Дедупликация сообщений** с раздельными фазами «в обработке» / «доставлено» — повтор от MAX после реконнекта не теряется и не дублируется
- **Детекция bridge-echo** — сообщения, отправленные вручную с телефона (не через бота), теперь тоже пересылаются в Telegram, при этом эхо самого бота корректно игнорируется
- **`/list`** — список известных чатов/каналов MAX прямо в Telegram, с постраничной догрузкой полного списка (MAX по умолчанию синхронизирует при логине только недавно активные чаты)
- **`/add` понимает всё, чем можно указать чат** — приглашение, публичный хэндл группы/канала, личную ссылку человека, номер телефона, id пользователя или id чата; вступает, если ещё не состоит, и привязывает, если уже состоит
- **«Избранное» (чат с самим собой в MAX)** тоже мостится: у него нет ни названия, ни собеседника, поэтому раньше он выглядел безымянным и оставался без карточки
- **`/del_max`** — выйти из чата на стороне MAX (покинуть группу, отписаться от канала, удалить диалог у себя), не выходя из Telegram; отдельно от `/del`, который трогает только топик
- **Безопасность**: SSRF-защита при скачивании вложений (только домены MAX), лимиты на размер скачивания/загрузки, редактирование токенов и секретов в debug-логах
- **Множественные `TG_ALLOWED_USER_IDS`**, фильтрация `MAX_CHAT_IDS`/`MAX_IGNORE_CHAT_IDS`
- **HTTP `/health`-эндпоинт** для Docker healthcheck / оркестраторов
- **TCP keepalive** на Telegram-клиентах — снижает частоту обрывов long-polling через обязательный SOCKS5-прокси
- Рассылка статусов подключения к MAX **во все** известные боту Telegram-группы, а не только в одну

> Проект полностью переведён на [PyMax](https://github.com/MaxApiTeam/PyMax). Старый собственный WebSocket-клиент и его переменные окружения больше не поддерживаются.

Каждый чат MAX становится отдельным форум-топиком в Telegram. Входящие сообщения из MAX (текст, фото, файлы, видео, голосовые, стикеры, контакты, локации, цитаты, пересланные) приходят в свой топик. Ответ написанный в этом топике уходит обратно собеседнику в MAX от твоего имени.

**Разные MAX-чаты можно направлять в разные Telegram-супергруппы** — не только в разные топики одной группы. Добавь бота админом (с правом «Управление темами») в несколько супергрупп, и используй `/bind`/`/add` в нужной группе, либо задай постоянную привязку заранее через `MAX_CHAT_ROUTES` в `.env`. Подробности — в разделе [Конфигурация](#конфигурация-env).

При создании топика автоматически постится и закрепляется карточка собеседника с именем, id и аватаром.

## Возможности

### MAX → Telegram
- Текст с сохранением форматирования (жирный / курсив / зачёркнутый / подчёркнутый / моноширинный / цитата / ссылки)
- Фото и видео с подписью; вложения одного сообщения объединяются в Telegram-альбом
- Полное скачивание нативных видео через PyMax с fallback на превью или текстовую пометку
- Документы любых типов, включая те, что приходят только с `fileId` без прямого URL (резолвится через PyMax)
- Голосовые и аудио (когда MAX отдаёт `_type=AUDIO`; для нового `_type=UNSUPPORTED` пока fallback на «не удалось скачать»)
- Стикеры
- Контакты, локации, ссылки-превью
- Пересланные сообщения и цитаты с подписью отправителя
- Сообщения, отправленные вручную с телефона/другого MAX-клиента (не через бота), тоже пересылаются — помечаются «📱 Вы (с телефона)»; при этом эхо самого бота (когда бот пересылает *свой же* ответ) корректно игнорируется, без дублей и петель
- **Отметки «прочитано»** — когда собеседник читает переписку в MAX, на последнее переславленное в Telegram сообщение автоматически ставится реакция ✅
- **Реакции** на сообщения в MAX — короткой строкой в соответствующем топике (например «👍 Реакция на сообщение: 👍×2»)
- Текстовая пометка о типе вложения, если медиа не удалось скачать или отправить
- Уведомления о статусе подключения к MAX — рассылаются **во все** известные Telegram-группы (не только в дефолтную), с троттлингом при частых обрывах

### Telegram → MAX
- Текст с форматированием (`STRONG`, `EMPHASIZED`, `STRIKETHROUGH`, `UNDERLINE`, `MONOSPACED`, `BLOCKQUOTE`, `LINK`)
- Фото через нативную загрузку MAX
- Видео через нативный `Video` в PyMax; **видеокружки** — через `VideoNote`, то есть остаются круглым видеосообщением и в MAX (раньше они молча терялись: не попадали в фильтр медиа-хендлера и не доходили до MAX вообще, даже без предупреждения в топик); документы и обычное аудио — как файлы
- Нативные голосовые сообщения через `pymax.Voice` с сохранением длительности — **с перекодированием под MAX**: телеграмовскую запись MAX отвергает (`AUDIO_VALIDATION_FAILED`) несмотря на то, что это уже Opus в OGG, поэтому она переводится через ffmpeg в Opus 48 кГц моно, который MAX принимает. ffmpeg ставится сам (пакет `imageio-ffmpeg` в зависимостях), системный используется в приоритете; если его нет вовсе — голосовое уходит как есть
- Telegram-альбомы собираются по `media_group_id` и отправляются одним сообщением MAX
- Реакция 👀 на успешную доставку, текст ошибки от MAX — на провал
- **Ничего не пропадает молча**: если тип вложения мост отправлять не умеет (стикер, опрос и т.п.), в топик приходит явное предупреждение. Раньше такие сообщения не доходили ни до какого обработчика и исчезали бесследно — именно так долго оставалась незамеченной пропажа видеокружков
- **Отметка «прочитано» (TG → MAX)** — как только ответ из топика успешно ушёл в MAX, чат отмечается прочитанным вплоть до последнего полученного оттуда сообщения (собеседник в MAX увидит статус «прочитано»). Важная оговорка: у Telegram Bot API нет события «пользователь открыл/прочитал сообщение» — боты физически не могут его получить. Поэтому триггером служит сам факт ответа в топике, а не момент открытия чата в Telegram; если вы просто прочитали, но не ответили, статус в MAX не обновится.

### Управление
- Авто-создание форум-топика на каждый новый чат MAX — **с правильным именем** даже для только что созданных групп: если чата ещё нет в стартовом снепшоте, имя запрашивается у MAX напрямую (раньше в таком случае топик по ошибке называли именем того, кто первым написал в чат, а не именем группы)
- Закреплённая карточка профиля при создании топика
- Команды: `/bind`, `/add`, `/list`, `/profile`, `/intro`, `/del`, `/help`
- Ограничение «отвечать может только определённый круг людей» — несколько Telegram user ID через запятую (`TG_ALLOWED_USER_IDS`)
- Фильтрация: слушать только выбранные чаты MAX (`MAX_CHAT_IDS`) или, наоборот, игнорировать конкретные (`MAX_IGNORE_CHAT_IDS`)
- SOCKS5-прокси для Telegram (`TG_PROXY`)
- Карта связок переживает рестарт (`state/topics.json`)
- Авто-переподключение к MAX; повторная доставка сообщения после сбоя обработчика не теряется и не дублируется (дедупликация с раздельным «в обработке» / «доставлено»)
- **Персистентная очередь доставки (SQLite, `state/outbox.db`)** — каждое сообщение в обе стороны (TG → MAX и MAX → TG) сохраняется на диск перед попыткой отправки и удаляется из очереди только после подтверждённой доставки. Если MAX или Telegram недоступны (обрыв связи, таймаут, любая другая ошибка), сообщение остаётся в очереди и переживает рестарт бота — фоновый цикл сам допытывается с нарастающей паузой (1 мин → 2 → 4 … потолок 1 час), пока доставка не подтвердится. Исключение — явный отказ MAX от самого содержимого (например, голосовое, которое MAX не принимает ни при какой попытке): такое сообщение не ставится в бесконечный повтор, а один раз помечается в топике («MAX отклонил это сообщение, повторять не буду») и убирается из очереди. Всё остальное — сеть, таймауты, недоступность MAX — остаётся в очереди.
- Защита от SSRF при скачивании вложений (только домены самого MAX), лимиты на размер скачивания/загрузки, редактирование токенов и других секретов в debug-логах
- HTTP-эндпоинт `/health` для Docker healthcheck / оркестраторов (`HEALTH_PORT`)
- **Маршрутизация разных MAX-чатов в разные Telegram-супергруппы** (не только в разные топики одной группы) — см. следующий раздел

## Маршрутизация в несколько Telegram-групп

По умолчанию (как и в оригинальном форке) один MAX-аккаунт превращается в одну Telegram-супергруппу с темами: каждый MAX-чат — свой топик. Этого хватает большинству, но иногда нужно развести переписку по смыслу — например, рабочие чаты в одну группу, личные в другую, чат конкретной команды — в третью, отдельную для этой команды.

Для этого чаты MAX теперь можно направлять в **разные** Telegram-супергруппы, а не только в разные топики одной. Есть два способа задать, какой MAX-чат куда идёт — их можно сочетать.

### Способ 1 — вручную через `/bind` / `/add` (проще всего)

1. Добавь бота администратором (с правом «Управление темами») в **каждую** Telegram-группу, куда хочешь что-то направлять — не только в основную из `TG_CHAT_ID`.
2. Зайди в нужную группу и напиши там `/bind <chat_id_в_MAX>` (или `/add <ссылка_max.ru>` для групп/каналов MAX).
3. Бот создаст топик **именно в этой группе** и с этого момента вся переписка с данным MAX-чатом — и туда, и обратно — идёт через неё.

Ничего в `.env` менять не нужно — привязка живёт в `state/topics.json` и переживает перезапуски.

### Способ 2 — заранее через `MAX_CHAT_ROUTES` в `.env`

Если хочешь, чтобы конкретные MAX-чаты сразу, с самого первого сообщения, попадали в нужную группу (а не в дефолтную `TG_CHAT_ID` с последующим ручным `/bind`) — пропиши маршруты заранее:

```env
MAX_CHAT_ROUTES={"-75107924425434": -1002233445566, "123456789": -1009988776655}
```

Формат — JSON-объект: ключ — `chat_id` в MAX (как строка), значение — `chat_id` целевой Telegram-супергруппы (число, обычно отрицательное, вида `-100…`). Бот должен быть администратором с «Управление темами» во всех перечисленных группах.

Чаты, которых нет ни в `MAX_CHAT_ROUTES`, ни среди уже привязанных через `/bind`, при первом сообщении автоматически создают топик в дефолтной `TG_CHAT_ID` — как и раньше.

### Как это разрешается на практике

Для каждого входящего сообщения из MAX целевая Telegram-группа определяется в таком порядке приоритета:

1. **Уже существующая привязка** в `state/topics.json` (если топик когда-либо создавался — через `/bind`, `/add` или автоматически) — это финальный источник истины, даже если он расходится с `MAX_CHAT_ROUTES`;
2. иначе — запись в **`MAX_CHAT_ROUTES`**, если для этого `max_chat_id` она задана;
3. иначе — **`TG_CHAT_ID`** (дефолтная группа).

То есть `MAX_CHAT_ROUTES` работает только для чатов, у которых ещё нет топика — если позже понадобится перенести уже привязанный чат в другую группу, проще всего `/del` старый топик и `/bind` его заново в нужной группе.

## Архитектура

```
  ┌────────────────┐    WebSocket    ┌──────────────────┐
  │ API MAX        │  ◄────────────► │   max2tg (app)   │
  │ через PyMax    │                 │  ├ PyMaxClient   │
  └────────────────┘                 │  ├ Resolver      │
                                     │  ├ TelegramSender│
  ┌────────────────┐    Bot API      │  └ tg_handler    │
  │ api.telegram.  │  ◄────────────► │                  │
  │ org            │                 │  state/topics.json│
  └────────────────┘                 └──────────────────┘
```

- `app/main.py` — точка входа: загружает `.env`, поднимает PyMax и Telegram Application (polling), привязывает их через TopicStore.
- `app/pymax_client.py` — единый клиент MAX: события, чаты, контакты, загрузка и скачивание медиа.
- `app/max_listener.py` — приём сообщений из MAX, маршрутизация в Telegram-топики, авто-создание топиков, постинг карточки.
- `app/resolver.py` — кеш контактов и чатов MAX.
- `app/tg_sender.py` — отправка в Telegram, `ensure_topic` (создание форум-топиков, переименование при появлении настоящего имени).
- `app/tg_handler.py` — команды и медиа из Telegram → MAX.
- `app/topics.py` — `TopicStore`: атомарно-сохраняемая JSON-карта `max_chat_id ↔ (telegram_chat_id, telegram_thread_id)`. Ключ реверс-поиска — пара `(chat_id, thread_id)`, а не только `thread_id`, поэтому один и тот же номер темы в разных супергруппах не конфликтует.

## Требования

- Python **3.12+** (для локального запуска)
- Docker + docker-compose v2 (для рекомендуемого деплоя)
- ffmpeg — нужен для отправки голосовых в MAX (см. [Известные ограничения](#известные-ограничения)). Ставить отдельно не обязательно: в Docker-образ он входит, а при локальном запуске бинарник приезжает с зависимостью `imageio-ffmpeg`; системный, если он есть, используется в приоритете
- Аккаунт MAX (`web.max.ru`)
- Супергруппа Telegram с **включёнными темами** (Topics / Forum) — можно несколько, если нужна маршрутизация по разным группам (см. [Маршрутизация в несколько Telegram-групп](#маршрутизация-в-несколько-telegram-групп))
- Telegram-бот (через [@BotFather](https://t.me/BotFather)) — администратор **каждой** такой супергруппы с правом «**Управление темами**»

## Установка

### 1. Подготовка Telegram

1. Создай супергруппу и в её настройках включи **«Темы» / «Topics»**.
2. У [@BotFather](https://t.me/BotFather) сделай нового бота → запиши **`TG_BOT_TOKEN`**.
3. Добавь бота в супергруппу администратором, поставь галку «Управление темами» (без этого права бот не сможет создавать топики).
4. Получи **`TG_CHAT_ID`** супергруппы: перешли любое сообщение из неё боту [@userinfobot](https://t.me/userinfobot) — он покажет id вида `-100…`.
5. (Опционально) Свой Telegram-user-id — для `TG_ALLOWED_USER_ID` (тот же @userinfobot в личке).
6. В настройках реакций супергруппы разреши «**Все эмодзи**», чтобы бот мог ставить 👀 на отправленные ответы.

### 2. Авторизация MAX

Проект использует только PyMax. По умолчанию применяется QR-вход:

```env
MAX_PYMAX_AUTH=qr
```

При первом запуске открой ссылку `PyMax QR authorization URL` из логов и подтверди вход в MAX. Если включена 2FA, интерактивный запуск дополнительно запросит пароль. Сессия сохранится в `state/pymax/pymax-qr.db`, поэтому каталог `state` нельзя удалять.

PyMax поддерживает два flow авторизации:

- `MAX_PYMAX_AUTH=sms` — TCP `Client`, первичный вход по `MAX_PHONE` и SMS-коду.
- `MAX_PYMAX_AUTH=qr` — WebSocket `WebClient`, первичный вход по QR; ссылка пишется в лог.

## Команды бота

Команды работают в **любой** супергруппе, куда добавлен бот (не только в `TG_CHAT_ID`) — `/bind` и `/add` создают топик именно в той группе, где их вызвали, тем самым направляя туда этот MAX-чат. Исключение — `/list`: он работает только в основной группе (`TG_CHAT_ID`). При заданном `TG_ALLOWED_USER_IDS` — только от перечисленных пользователей.

| Команда | Что делает |
|---|---|
| `/bind <chat_id или URL> [название]` | Создать топик под конкретный чат MAX **в той группе, где вызвана команда**. URL вида `https://web.max.ru/<chat_id>` тоже принимается. |
| `/add <ссылка, номер или id>` | Привязать чат MAX к новому топику **в той же группе**, вступив в него, если ещё не состоишь. Формы — в таблице ниже. |
| `/list` | (только в `TG_CHAT_ID`) Список всех чатов MAX — группы, каналы и личные сообщения. id, веб-ссылка и (если MAX её прислал) приглашение в чат идут моноширинными строками, чтобы копировать в `/bind`. |
| `/profile` | (в топике) Показать профиль собеседника MAX: имя, id, аватар. |
| `/intro` | (в топике) Перепостить и закрепить карточку профиля. |
| `/del` | (в топике) Удалить топик и снять связь с MAX-чатом (с подтверждением). В самом MAX ничего не меняется. |
| `/del_max <chat_id>` | (только в `TG_CHAT_ID`) Выйти из чата **в самом MAX**: покинуть группу, отписаться от канала или удалить диалог — только у себя. С подтверждением, необратимо. Топик Telegram остаётся. |
| `/help` | Список всех команд. |

### Что понимает `/add`

| Аргумент | Что делает |
| --- | --- |
| `https://max.ru/join/...` | Приглашение в группу/канал: бот вступает и привязывает топик. |
| `https://max.ru/id..._gos` | Публичная ссылка-хэндл группы/канала: если вы уже подписаны, привязка сразу, без запросов к MAX. |
| `https://max.ru/u/...` | Личная ссылка человека. Токен читает только сам MAX (`LINK_INFO`); если он отвечает пользователем — привязывается диалог с ним. |
| `+79991234567` | Поиск человека по номеру телефона средствами MAX. |
| `6633015816` | id пользователя: id личного чата вычисляется из пары участников. Привязка только если MAX подтверждает такого пользователя. |
| `-69369957050939` | id группы или канала: привязывается сразу, как `/bind` — вступить по id в MAX нельзя. |

Различие между номером и id — только явный `+`: в остальном это одни и те же цифры. Положительное число считается id пользователя, кроме случая, когда оно совпадает с уже известным чатом (id личного чата тоже положительный).

### Выход из чата на стороне MAX

`/del` и `/del_max` — разные вещи, намеренно. `/del` живёт в топике и убирает только Telegram-сторону: топик и привязку; в MAX чат остаётся, и его можно привязать заново. `/del_max` действует в самом MAX и по типу чата: группу — покинуть, канал — отписаться, диалог — удалить.

Диалог удаляется **только у вас** (`for_all=False`): в pymax у этого вызова по умолчанию стоит `for_all=True`, что стёрло бы переписку и у собеседника, поэтому наружу параметр не выведен вовсе. «Избранное» команда удалять отказывается — это ваши собственные заметки.

Команда доступна только в основной группе (`TG_CHAT_ID`), спрашивает подтверждение и не трогает топик: после выхода он останется на месте, пока вы не уберёте его через `/del`. Учтите, что после выхода из группы или канала мост перестаёт получать оттуда сообщения, а удалённый диалог появится снова, если человек напишет вам ещё раз.

### «Избранное»

Чат с самим собой в MAX — обычный чат для моста: он виден в `/list` под названием **Избранное**, привязывается как любой другой (`/bind <его id>` или `/add <его id>`), и топик становится заметками, которые видны и в MAX, и в Telegram. В MAX это диалог, единственный участник которого — вы; поэтому у него нет ни названия, ни собеседника, и мост подставляет имя сам.

## Известные ограничения

1. **Голосовые MAX → TG** могут приходить без доступного URL. В таком случае мост отправляет текстовую пометку вместо потери сообщения.
2. **Ссылки `/u/<token>`** могут не открываться через `/add`: pymax умеет только `join/<токен>`, остальное мост отдаёт MAX через `LINK_INFO` и зависит от его ответа. Публичные хэндлы вида `max.ru/id<цифры>_gos` при этом работают, если вы уже подписаны на этот чат — мост узнаёт ссылку среди своих чатов. Вступить в новый чат мост может только через join-ссылку, и только если это позволяет ваш MAX-аккаунт (бывает ограничение `error.user.restricted.join`).
3. **Лимиты Telegram Bot API** и значения `MAX_DOWNLOAD_MB`/`TG_UPLOAD_MB` ограничивают размер передаваемых файлов.
4. **Реакции MAX → TG** не привязываются к конкретному пересланному сообщению — приходят отдельной строкой в топике, а не как реакция именно на тот пост (в отличие от отметки «прочитано», которой достаточно самого *последнего* сообщения в чате). Кастомные emoji-реакции Telegram тоже не позволяет ставить ботам, поэтому используется обычная `✅`/`👀`.
5. **Phone / about** в `/profile` могут отсутствовать, если MAX не вернул эти поля.
6. **Форматирование Telegram → MAX** пока отправляется как plain text: публичный PyMax API не принимает Telegram entities напрямую.
7. **Read-receipt TG → MAX работает по факту ответа, а не открытия чата.** Telegram Bot API не сообщает боту, когда человек прочитал сообщение — такого события просто не существует для ботов. Поэтому чат в MAX отмечается прочитанным в момент, когда ваш ответ из топика успешно доставлен, а не когда вы просто открыли/просмотрели топик в Telegram.
8. **Отправка голосовых из Telegram в MAX в `maxapi-python` (≤2.4.1, актуальная на момент написания) не работает вовсе** — см. [PyMax#103](https://github.com/MaxApiTeam/PyMax/issues/103). Мост подменяет `upload_voice` целиком (`app/pymax_client.py`, `_patch_voice_upload_user_agent`). Рецепт установлен перебором против живого сервера; все три части обязательны:
   - **multipart-форма вместо сырого тела с `Content-Range`** (библиотека копирует его из video-загрузки) — на любое сырое тело MAX отвечает `BAD_REQUEST`;
   - **ссылка на вложение по `audioId`, а не по токену video-пайплайна.** Через него голосовые и грузятся, поэтому `MSG_SEND` уходит с `{_type: AUDIO, token: <video-токен>}`, а MAX резолвит этот токен как видео и отвечает `errors.process.attachment.video.not.ready` — бесконечно, сколько ни жди. Нужная форма в библиотеке уже есть (`{_type: AUDIO, audioId: ...}` для вложения без токена), но это мёртвый код: токен проставляется всегда;
   - **перекодирование записи в Opus 48 кГц моно** через ffmpeg. Телеграмовский файл — уже Opus в OGG, но MAX бракует его с `AUDIO_VALIDATION_FAILED`; контейнер при этом ни при чём (WebM-ремукс отвергается так же), дело в том, как Telegram кодирует свои голосовые.

   Отдельная причина, по которой это так долго выглядело загадкой: **ошибки загрузки MAX отдаёт с HTTP 200**, а настоящий вердикт кладёт в тело ответа, которое библиотека не читает (в её исходниках на этот счёт стоит TODO). Мост тело логирует.

   Ещё два патча (`_patch_api_error_not_ready_matching`, `_patch_voice_ready_resolution`) чинят сравнение кода ошибки и классификацию события готовности — они относятся к тому же video-пайплайну и остаются как страховка. Все патчи безвредны, если апстрим это починит.
